# AI 경진대회 출품 개선 계획서
> 대상 프로젝트: **현장 조사표 DB화** (field-survey-db)
> 전제: 외부 AI API(Claude 등 클라우드) 사용 **허용**
> 작성 관점: "실무 도구"를 "AI 경진대회 수상작"으로 끌어올리기

---

## 0. 한 줄 전략
> **"규칙 기반 파서 + 옵션 AI" → "AI(Vision-LLM)가 추출을 직접 수행하고, 규칙은 검증·신뢰도로 보조하는 하이브리드"** 로 무게중심을 옮긴다.
> 그리고 그 성능을 **숫자(정확도·자동화율·절감시간)로 증명**한다.

---

## 1. 심사 기준 vs 현재 위치

AI 경진대회 심사는 보통 아래 4축이다. 현재 프로젝트의 강·약점을 매핑하면:

| 심사축 | 현재 상태 | 평가 |
|--------|-----------|------|
| **AI 기술 혁신성/활용도** | 추출은 좌표·라벨 규칙 기반. LLM은 "박스 위치 제안"만 하는 옵션 | 🔴 약점 (핵심 개선 대상) |
| **문제 해결 임팩트** | 실존하는 수천 장 수기입력 문제, 명확한 사용자 | 🟢 강점 |
| **완성도/동작** | 웹앱·OCR·포터블 빌드까지 end-to-end 동작 | 🟢 강점 |
| **일반화/확장성** | 샘플 양식 1건 기준 규칙, E·B 서식 미구현 | 🟡 보통 |

**결론:** 강점(실문제·완성도)은 이미 충분하다. **AI 혁신성 축이 병목**이므로 여기에 자원을 집중한다.

## 2. 개선 전략 3축

### 축 A. AI를 추출의 주역으로 (Vision-first 추출)
현재: 사람이 박스를 그리거나 규칙이 좌표를 계산 → 새 양식마다 재작업.
개선: **PDF 페이지 이미지를 Claude Vision에 통째로 입력 → 목표 스키마(JSON)로 직접 채움.**
- 사람이 박스를 안 그려도, 처음 보는 양식도 자동 DB화 → **"어떤 양식이든 넣으면 된다"** 가 데모 킬러 포인트.
- 스캔 PDF도 OCR 좌표 조합 없이 Vision이 직접 읽음 → OCR 오차(위도 349 등) 문제 완화.
- 기존 규칙 기반 경로는 버리지 않고 **교차검증·폴백**으로 재활용 → "AI 추출 + 규칙 검증" 신뢰성 서사.

### 축 B. 성능을 숫자로 증명 (평가 체계)
- 정답 라벨을 붙인 **골드셋(20~30건, A~E·텍스트/스캔 혼합)** 구축.
- 지표: **필드 단위 정확도 %**, **완전자동 통과율**(사람 수정 0건 비율), 서식별 분해.
- **비교표**: 규칙 기반 vs AI-Vision vs 하이브리드 → 슬라이드 한 장으로 설득.
- 부가: 건당 비용·처리시간 측정.

### 축 C. 신뢰성 & 완결성
- 모델이 **필드별 신뢰도(confidence)** 반환 → 낮은 필드만 기존 검수 UI로 강조 → "AI + 사람 검증" 흐름.
- 미구현 **E 횡적연속성·B 대표지점**을 규칙 하드코딩 대신 **스키마 정의만으로 AI가 채우게** → 개발비용↓, 일반화 서사↑.

## 3. 단계별 실행 계획

> 각 Phase는 독립적으로 데모 가치가 있다. 시간이 부족하면 Phase 1~2만으로도 출품 가능.

### Phase 1 — Vision-LLM 추출 파이프라인 (핵심, 최우선)
- **범위**: PDF 페이지 렌더 이미지 + 서식별 목표 스키마 → Claude Vision → 구조화 JSON.
- **산출물**: `core/extraction/vision_extract.py`, 서식별 JSON 스키마 세트.
- **재사용**: 페이지 렌더(pymupdf)·서식 판별(form_detector)·엑셀 생성은 그대로.
- **효과**: "AI가 추출을 직접 한다"는 핵심 서사 확보. 새 양식 무설정 동작.

#### Phase 1 하위 목표 — 사용자 지적 2대 문제 해결 (강건화)
현재 규칙 경로의 실제 약점(코드 근거)과 개선 방향:

**(가) "양식이 틀어짐" — 절대좌표 폴백 제거**
- 현상: `apply_pixel_template`의 유기적 추출(`_cell_anchor_value`, pdf_pipeline.py:293)은 **벡터 표 선**이 있어야 작동. 스캔·손글씨(OCR)는 칸이 없어 **절대좌표(bbox)로 폴백** → 페이지가 밀리면 값 어긋남.
- 개선:
  1. **텍스트·OCR 단어를 동일한 "단어+위치" 레이어로 통일** → 표 선 감지에 의존 않고 라벨을 좌표로 탐색.
  2. **라벨 퍼지 매칭**(OCR 오타·띄어쓰기 허용).
  3. 박스를 절대좌표가 아니라 **앵커 라벨 기준 상대 위치(방향+간격)**로 저장 → 통째로 밀려도 값이 라벨을 따라감.

**(나) "제목 바뀌면 다른 양식" — 배치를 정체성으로**
- 현상: PDF 경로 `match_pages`(pdf_pipeline.py:344)는 **라벨 집합 겹침 비율(≥0.35)**만 봄. 2D 배치는 안 봄 → 변형이 임계 아래면 매칭 실패. (표 경로 `form_detector`는 이미 제목 무관·라벨 시그니처 기반이라 양호)
- 개선: **양식 정체성 = 라벨들의 전체 공간 배치(레이아웃 지문)**. 상대적 2D 위상으로 유사도 매칭, **제목은 지문에서 제외**.

**(다) Vision-LLM이 (가)+(나)를 원천 해결**
- Vision은 페이지를 통째로 이해 → 밀림·제목변경·스캔에 자연 강건.
- **하이브리드**: 1차 규칙 앵커(빠르고 무료) → 못 풀거나 틀어진 페이지만 2차 Vision → 두 결과 교차검증으로 신뢰도. 비용↓·정확도↑ 동시 달성.

### Phase 2 — 정확도 평가 체계 (설득력)
- **범위**: 골드셋 라벨링 포맷 정의 → 자동 채점 스크립트 → 리포트(정확도·통과율·서식별).
- **산출물**: `eval/gold/*.json`, `eval/run_eval.py`, `eval/REPORT.md`.
- **효과**: "정확도 9X%" 정량 근거. 규칙 vs AI 비교표.

### Phase 3 — 하이브리드 신뢰성 (안정성)
- **범위**: AI 추출 + 규칙 교차검증 → 불일치·저신뢰 필드 자동 플래그 → 검수 UI 강조.
- **산출물**: 신뢰도 병합 로직, 검수 화면 신뢰도 뱃지.
- **효과**: 실무 신뢰성 = 심사 가점. 환각(hallucination) 방어 서사.

### Phase 4 — 서식 커버리지 완성 (완결성)
- **범위**: E 횡적연속성·B 대표지점 스키마 추가(코드 하드코딩 대신 스키마+AI).
- **효과**: "전 서식 커버" 데모.

### Phase 5 — 발표/데모 패키징 (전달력)
- **범위**: 60초 라이브 데모 시나리오, Before/After 임팩트 수치, 아키텍처 다이어그램, 발표자료.
- **산출물**: `docs/demo_script.md`, 아키텍처 이미지, 발표 슬라이드 개요.

## 4. 임팩트 스토리 (발표용 수치 뼈대)
- **Before**: 수기 입력 약 __분/장 × 수천 장 = __시간/년.
- **After**: 자동 __초/장 → __% 시간 절감, 인건비 __원 절감.
- **정확도**: 완전자동 통과율 __%, 필드 정확도 __%.
- **범용성**: 하천 조사표를 넘어 "현장 조사표 일반"으로 확장 가능(원래 명세의 성장 아이디어와 일치).

## 7-1. API 키 아키텍처 (확정: 프록시 방식)
**목표**: 사용자(대회 심사자·팀원)는 키를 몰라도 AI가 동작. 팀 계정 키는 사용자 PC에 절대 내려가지 않음.

```
사용자 exe  →  Cloudflare Worker (프록시, 무료)  →  Claude API
              └ ANTHROPIC_API_KEY = Worker secret (여기서만 존재, 노출 안 됨)
```

**동작**: exe의 anthropic 클라이언트 `base_url`을 Worker 주소로 바꾼다. 실데이터는 Worker를 "통과"만 하고 저장/로그 안 함.

**남는 위험과 대응 (정직하게)**:
- exe는 프록시에 인증할 **앱 토큰**이 필요 → 이건 exe에서 추출될 수 있음. **그러나** 진짜 Claude 키와 달리:
  - 토큰은 **쿼터·레이트리밋** 걸어 유출돼도 **피해 상한**이 정해짐.
  - 언제든 **폐기·교체** 가능 (진짜 키는 서버에서 안 건드림).
- Worker에 **모델 고정·max_tokens 상한·요청수 제한**을 걸어 비용 폭주 방어.
- Worker는 **요청 본문(실데이터) 로깅 금지**.

> 즉 "완벽한 은닉"이 아니라 "유출돼도 손실이 제한되고 즉시 차단 가능한" 실무적으로 올바른 구조.

**구축 위치**: W1에 Phase 1과 함께 (Phase 1 자체가 API 접근을 필요로 하므로 같이 세움).
